Normal mode

Receipts watches every batch and proves why a number moved. In this mode it cannot change data: nothing here plants a fault or rewrites a table. The only write a person can make is approving a proven correction.

To plant faults, break the pipeline or run the red team on the built-in synthetic data, start it in lab mode: receipts demo --lab.

LAB MODE

Break the pipeline

Lab mode, synthetic data only. Plant one fault into tonight's incoming RAW batch with the same SQL the scenarios use. Published history and the clean copies in LANDING are never touched. Then watch the gate work, step by step.

Red team: where Receipts breaks
